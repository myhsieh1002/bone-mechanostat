## 3. 可能原因（原始記錄；探針結果見第 6 節）

領先假說：**抗體輸入是階梯函數，`ode15s` 跨越不連續點的步長選擇不同**。稿件 §4.5 自己就寫了「The antibody is a step function, which sharpens the withdrawal transient」。自適應剛性解算器若沒有用 Events 或 `MaxStep` 把不連續點釘住，不同版本／不同執行緒排程會在階梯附近走出不同的步長序列，誤差就集中在這條路徑的下游——正好符合「平滑標的 1e-12、階梯驅動標的 1e-2」的型態。

已經**排除**的解釋：

- **不是晶片架構差異**：舊輸出的 MAT 標頭是 `Platform: MACA64`，與本機（MacBookPro18,2、arm64）相同。不是 Intel → Apple Silicon 的遷移造成的。
- **不是參數被改動**：`data/` 與 `src/` 自 2026-11-09 的 initial snapshot 以來沒有任何 commit。（注意：git 歷史只從 11-09 開始，更早的狀態無法用本地 git 驗證，公開 repo 才有完整歷史。）
- **不是半成品或壞檔**：27 個中斷前產出的檔案全部通過 `file` 格式檢查，無截斷。

**尚未排除**：MATLAB 版本差異（稿件 §2.4 寫 R2026a，本機與版本政策是 R2025b Update 5）、執行緒數相依、或真正的非決定性。

### 已安排的鑑別探針

2026-11-18 的重跑腳本加了 Step 1b：在同一個 MATLAB 行程裡連跑 `evalTargets` 三次——4 執行緒兩次、1 執行緒一次。

| 結果 | 判定 |
|---|---|
| 同執行緒數兩次就不同 | **非決定性**（最嚴重：同機同版同參數都重現不了） |
| 兩次相同、1 執行緒不同 | **執行緒數相依**（可用固定 `maxNumCompThreads` 釘住） |
| 三次全同，但與凍結值不同 | **環境相依**（版本／機器），在該環境內可重現 |

### 6.1 決定性探針：三次逐位元相同

同一個 MATLAB 行程內連跑 `evalTargets(p, holdout=true)` 三次——4 執行緒兩次、1 執行緒一次：

| V2 | 1.2201650980 | 1.2201650980 | 1.2201650980 | 0 | 0 |
| V7 | 0.6630156971 | 0.6630156971 | 0.6630156971 | 0 | 0 |
| V8 | 12.6892278299 | 12.6892278299 | 12.6892278299 | 0 | 0 |

更強的佐證：這次的結果與 11-17 23:27 那次（被 kernel panic 中斷的執行）也**逐位元相同**，中間隔了一次當機、一次重開機、70 分鐘；連輸出的 **Fig2–Fig6 TIFF 檔都是逐位元相同**。

### 6.2 結論

| 假說 | 判定 |
|---|---|
| 非決定性 | ❌ **排除**（同行程同執行緒數三次全同，跨當機重開機也全同） |
| 執行緒數相依 | ❌ **排除**（1 執行緒與 4 執行緒逐位元相同） |
| 晶片架構 | ❌ **排除**（舊輸出標頭同為 MACA64） |
| 參數被改動 | ❌ **排除**（`data/`、`src/` 無 commit） |
| **環境相依（最可能是 MATLAB 版本）** | ✅ **僅存假說** |

也就是說：**在這台機器、這個版本下，模型完全可重現**；它只是穩定地給出與 v2.25 封存值不同的答案。領先嫌疑是 MATLAB 版本——稿件 §2.4 寫 **R2026a**，本次與 11-17 都是 **R2025b Update 5**。

> ⚠️ HANDOFF 原本寫「v2.25 凍結值…R2025b 本機 2026-10-19 重跑確認」。這句話與今天的證據矛盾：R2025b 在本機**決定性地**給出 V8 = 12.6892，不是 12.4593。所以 10-19 那次「確認」要嘛不是完整的 `evalTargets` 重跑，要嘛不是在現在這台機器／這個版本上做的。
